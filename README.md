# Turtle Courier

Репетиция «Новой высоты» для TurtleBro в Webots R2025a и ROS 2 Humble.
Поле 3,40 × 3,44 м реконструировано по фотографиям. Есть шесть парковок,
центральная улица, боковые заезды, красные корпуса, синий Т-образный корпус и
жёлтые кубы. Размеры приблизительные. [Запуск на реальном TurtleBro](#запуск-на-реальном-turtlebro).

```bash
cd ~/zed/ros2/turtle-courier
docker build -t turtle-courier:humble .
mkdir -p results
docker run --rm --init --user "$(id -u):$(id -g)" -e HOME=/tmp -e USER=robot \
  -v "$PWD/results:/results" turtle-courier:humble
```

По умолчанию старт и цель выбираются случайно и всегда различаются.
`--seed 17` повторяет жеребьёвку и случайную ориентацию. `--yaw-offset 180` задаёт разворот вручную. Можно явно указать
`--start 21 --goal 23`. Тренировочные ID: 21, 22, 23, 25, 26, 27.
На фото крупным планом читается ArUco 27 из семейства 4×4. Остальные ID
и координаты сверяйте с вашим экземпляром поля. Настройки лежат в `field.py`.

Запуск с окном под X11/XWayland:

```bash
docker run --rm --init --user "$(id -u):$(id -g)" -e HOME=/tmp -e USER=robot \
  -e DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix:ro \
  -v "$PWD/results:/results" turtle-courier:humble --gui --start 21 --goal 23
```

Если сеанс требует Xauthority, передайте контейнеру файл текущей X11-сессии
только для чтения и задайте `XAUTHORITY` на его путь внутри контейнера.
После финиша окно остаётся открытым. Для нового заезда закройте его и
повторите команду. `--clear` убирает дополнительный куб с центральной дороги
и оставляет шесть кубов на островках, как на фото.

`navigate.py` узнаёт старт по крупной ArUco в кадре, останавливает поиск и по свежему кадру привязывает относительную
одометрию к парковке и строит кратчайший путь по графу дорог. Ультразвук
закрывает заблокированный участок, робот возвращается к предыдущему узлу
и перепланирует маршрут по боковому проезду. В целевой парковке требуется
свежий кадр именно с заданной меткой. Стартовое место передаётся только Webots.
Модель имеет дифференциальные колёса, энкодеры, IMU, обычную камеру и
передний сонар. Эталонную позу Webots читает только проверка результата.
JSON сохраняет фактический и распознанный старт, результат, время,
зазор, факт контакта и отклонение от центра парковки.

Прогон всех направленных пар в контейнере:

```bash
./verify.sh "$PWD/results/matrix" blocked
./verify.sh "$PWD/results/matrix-clear" clear
```

## Запуск на реальном TurtleBro

Запускайте `navigate.py` на Raspberry Pi по SSH со штатными драйверами робота
и ROS 2 Humble. Для этого достаточно трёх Python-файлов. Документация
TurtleBro2 описывает конфигурацию с Jazzy. Имена и типы топиков проверьте
на выданном роботе. [Быстрый старт TurtleBro2](https://ros2.turtlebro.ru/quickstart.html)

### Подключение и проверка топиков

На ноутбуке откройте Bash в корне этого репозитория и подставьте выданный логин
и IP. Если в сети работает mDNS, можно использовать имя вида `turtlebroNN.local`.

```bash
ROBOT=pi@192.0.2.10
ssh "$ROBOT" 'mkdir -p ~/turtle-courier' &&
  scp navigate.py field.py vision.py "$ROBOT:turtle-courier/" &&
  ssh "$ROBOT"
```

На роботе выполните команды в Bash. Если в штатной сборке есть свой ROS workspace
или настройки DDS, подключите их так же, как для штатных узлов TurtleBro.

```bash
source /opt/ros/humble/setup.bash
cd ~/turtle-courier
CAMERA=/front_camera/image_raw
ros2 topic list -t
ros2 topic info /cmd_vel -v
ros2 topic echo /odom --once --field header
ros2 topic echo "$CAMERA" --once --field encoding
python3 -c 'import rclpy, cv2, numpy; print(cv2.aruco.DICT_4X4_50)'
```

На `/cmd_vel` должен быть подписчик драйвера с типом `geometry_msgs/msg/Twist`.
Узел ждёт `nav_msgs/msg/Odometry` на `/odom` и `sensor_msgs/msg/Image` с кодировкой
`mono8`, `rgb8`, `bgr8`, `rgba8` или `bgra8`. Если камера публикует под другим именем,
укажите его в `CAMERA`. Если в системном Python на Ubuntu
не хватает `cv2.aruco`, установите `python3-opencv`, если на роботе разрешено ставить
пакеты.

В симуляторе сонар публикует в `/ultrasonic/front`. На роботе выберите фактический
топик типа `sensor_msgs/msg/Range`. В штатной комплектации TurtleBro2 указан
лидар. Если доступен только `/scan`, текущему узлу понадобится адаптер под
`LaserScan` или доработка. Использование лидара на модуле согласуйте с судьями.
[Комплектация TurtleBro2](https://ros2.turtlebro.ru/)

```bash
SONAR=/ultrasonic/front  # Подставьте топик, найденный на роботе.
ros2 topic echo "$SONAR"
```

Поднесите кубик к датчику и проверьте, что `range` уменьшается, а `header.stamp`
обновляется. Дальность должна быть в метрах, камера, одометрия и дальномер должны
использовать одну шкалу времени. Если метка времени дальномера расходится с
одометрией больше чем на 0,5 с или сообщений дальномера нет, узел отправляет
нулевую команду при обработке `/odom`.

### Привязка к полю

- В [`field.py`](field.py) обновите `POSES` для шести реальных ID. Для каждой
  парковки измерьте координаты центра ровера в метрах и угол в радианах, когда
  он стоит носом к метке. В `NODES` и `EDGES` задайте центры проездов и связи между
  ними. Проверьте запас до кубиков при прямом ходе, разворотах и реверсе.
- Измерьте `TAG_DISTANCE` от центра ровера до метки, `CAMERA_X` от центра
  разворота до камеры по продольной оси и `ARUCO_SIZE` по внешней чёрной рамке
  без белого поля. Проверьте все шесть меток по кадрам камеры. Словарь задаётся
  в [`vision.py`](vision.py). Порог распознавания старта рассчитан на расстояние
  от камеры до метки примерно до 0,39 м. Если метку видно, но старт не определяется,
  проверьте её размер в кадре и порог `start_min_area`.
- Для `--fov` используйте горизонтальный угол обзора в радианах. Расчёт угла
  до метки в узле предполагает перспективное изображение. Для широкоугольной
  камеры укажите выпрямленный поток в `CAMERA`, если искажения влияют на угол до метки.
  Для выпрямленного кадра с центрированной оптической осью
  `FOV = 2 × atan(ширина_кадра / (2 × fx))`, где `fx` берётся из калибровки
  выпрямленного потока в пикселях. [Камера и калибровка TurtleBro2](https://ros2.turtlebro.ru/40-devices/20-camera.html)

### Пробный заезд

Остановите телоп и другие узлы, которые публикуют команды движения. Для первой
проверки поставьте ровер в стартовый карман носом к метке, оставьте колёса
вывешенными и введите ID этой же парковки как цель. При поиске метки узел может
начать поворот. Ожидаемые сообщения в логе — `Camera found start ArUco …` и
`target ArUco confirmed in bay`.

```bash
read -r -p 'Горизонтальный FOV в радианах: ' FOV
read -r -p 'ID целевой парковки: ' GOAL
python3 navigate.py --goal "$GOAL" --camera "$CAMERA" --sonar "$SONAR" \
  --fov "$FOV" --speed .08
```

На поле введите ID цели от судьи и повторите команду. Старт скрипт определит
камерой. `--speed .08` ограничивает линейную скорость до 0,08 м/с. Текущий
лимит заезда составляет 105 с с первого сообщения `/odom`. При блокировке
проезда узел возвращается по пройденному участку и ищет открытый путь по графу.

Держите физический стоп под рукой. Для остановки через ROS прервите
`navigate.py` через `Ctrl+C`, затем отправьте нулевую команду.

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.0}}'
```

Заезды и перепланирование проверены в Webots. Для реального поля нужны замеры,
проверка датчиков и пробный заезд под наблюдением.

- [Управление и одометрия TurtleBro2](https://ros2.turtlebro.ru/40-devices/40-motor.html)
